### 68 Why Lasso Creates Sparsity

**Sources**
1. CampusX, "Why Lasso Regression creates sparsity?", FN4aZPIAfI4, 24:30. Timed text: `transcripts/teaching-video/68-campusx-lasso-sparsity.txt`.

**Teaching path**
1. [CX 00:00–02:07] The interview question: Ridge coefficients get close to 0 but never reach it; Lasso coefficients hit exactly 0 as λ grows, which is why Lasso does feature selection.
2. [SQ-vis 00:30–02:02] Picture first: a weight–height scatter, a horizontal line (slope 0), residuals drawn; then the sum of squared residuals (SSR) plotted against slope 0, 0.2, 0.4 … traces a parabola with its bottom at slope 0.45. Why it clicks: the reader sees "best slope = lowest point of a curve".
3. [SQ-vis 02:02–05:50] Add the Ridge (squared) penalty: curves for λ = 0, 10, 20, 40 (blue, orange, green, purple). Worked numbers: at λ = 10, slope 0.2 gives penalty 0.4, slope 0.4 gives 1.6. The lowest point slides towards 0 but the curve stays a smooth parabola, so the minimum never lands on 0 (even λ = 400, at 07:58).
4. [SQ-vis 05:50–07:58] Same plot with the Lasso (absolute-value) penalty: a kink appears at slope 0 at λ = 10, grows at 20, and at λ = 40 the lowest point is the kink itself, slope exactly 0, so weight is dropped from the model. Why it clicks: the corner of |m| is visible as a "V" the minimum falls into.
5. [CX 02:07–12:56] Now the algebra on one feature: the OLS slope formula, then the Lasso loss Σ(yᵢ − mxᵢ − b)² + 2λ|m| (the 2 "for mathematical convenience", 06:29). |m| has no derivative at 0, so split into cases m > 0 and m < 0, giving m = (S − λ)/D and m = (S + λ)/D.
6. [CX 13:31–18:54] Worked example S = 100, D = 50: λ = 0 → m = 2; λ = 50 → 1; λ = 100 → 0; λ = 150 → the m > 0 formula gives −1, so the m < 0 formula must be used, which gives (100 + 150)/50 = 5, back on the wrong side; the algorithm stops at 0. Two answers: why it reaches 0 (λ in the numerator) and why it stays there.
7. [CX 19:25–21:34] Mirror case S = −100: −2, −1, 0 at λ = 0, 50, 100; at λ = 150 the other formula gives −5, so again stuck at 0.
8. [CX 22:05–23:40] Ridge contrast: m = S/(D + λ); λ only in the denominator, so even λ = 1 crore leaves m small but non-zero.
9. [SQ-lasso 05:12–07:15] Payoff with many features: the "astrological sign" and "air speed of a swallow" terms go to exactly 0, leaving a simpler model; Lasso helps when many variables are useless, Ridge when most are useful.

### 69 Elastic Net Regression

**Sources**
1. CampusX, "ElasticNet Regression | Intuition and Code Example | Regularized Linear Models", 2g2DBkFhTTY, 11:41. `69-campusx-elastic-net.txt`.
2. StatQuest, "Regularization Part 3: Elastic Net Regression", 1dKRdX9bfIo, 5:19. `69-statquest-elastic-net.txt`.

**Teaching path**
1. [SQ 00:31–01:33] Recap with one picture: a size model with useful terms (weight, high-fat diet) and silly ones (astrological sign, air speed of a swallow). Lasso deletes the silly terms; Ridge keeps all and shrinks.
2. [SQ 01:33–02:05 + CX 02:37–03:41] The problem: a model with millions of parameters (SQ) or a dataset with too many columns to know which matter (CX), so we cannot choose Ridge or Lasso in advance.
3. [SQ 02:36–03:40] The fix: least squares + λ₁·(Lasso penalty) + λ₂·(Ridge penalty), each with its own λ, both chosen by cross-validation. The four corners: both 0 → least squares; only λ₁ → Lasso; only λ₂ → Ridge; both → hybrid. (Same as the Note's penalty-plane figure.)
4. [CX 04:15–06:52] scikit-learn's two settings: alpha = a + b (total strength) and l1_ratio (the mix), default alpha 1, l1_ratio 0.5 (a = b = 0.5).
5. [SQ 03:40–04:41 + CX 07:26–07:56] Correlated features: Lasso keeps one of a correlated group and drops the rest; Ridge shrinks them together; Elastic Net groups them, keeping or removing them together. CX's everyday pair: height and weight rise together (multicollinearity).
6. [CX 07:56–09:30] Code on the diabetes data: linear regression R² ≈ 0.433 (as captioned), Ridge best at alpha 0.1, Lasso best at 0.01, Elastic Net with alpha 0.005 and l1_ratio 0.9 slightly better; tune alpha and l1_ratio with GridSearchCV or RandomizedSearchCV.
7. [CX 09:30–10:31] The same model from `SGDRegressor(penalty="elasticnet")`; `ElasticNet` is the optimised class.

- Little. The Note has the penalty plane, alpha/l1_ratio map, morphing region and grouping-effect experiment.
- The beginner hook of beat 2 ("we often cannot know which features are useless, so we cannot pick Ridge or Lasso") is not stated as the motivation in §1; the Note starts from the formula.
- No picture of beat 1 (the useful vs silly terms equation) to recall Ridge vs Lasso before mixing them.

**Animation ideas**
1. Plotly frames: the Note's grouping experiment (three copies of one signal + three noise features), bar chart of coefficients as l1_ratio sweeps 0 → 1 at fixed alpha: Ridge-like sharing → Elastic Net sharing with noise at 0 → Lasso dropping x₁.
2. Plotly frames: diabetes coefficient paths against alpha for l1_ratio 0.1, 0.5, 0.9, 1 side by side, to show how the mix decides how fast coefficients hit 0.
(The Note's existing morphing-region GIF already covers the shape idea.)

**CampusX vs the others**
- The idea of combining both penalties: StatQuest is clearer (four λ₁/λ₂ cases, one picture each); CampusX is clearer on the scikit-learn mapping (alpha, l1_ratio, defaults) and gives the code-first diabetes comparison. Use StatQuest's four cases first, then CampusX's mapping.
- CampusX adds the code and the `SGDRegressor` route; StatQuest adds the grouping explanation in one sentence each for Lasso, Ridge and Elastic Net.
- Clash: CampusX says l1_ratio = a/(a + b) with a on the Ridge term, so l1_ratio 0.9 means "90% Ridge, 10% Lasso" (CX 04:46–05:48, and again at 08:57 "giving more weight to Ridge"). The Note is right (§3, r = b/(a + b), and its Extra warns against this exact slip).

- CampusX vs Note on l1_ratio (above): the Note is right, per the scikit-learn `ElasticNet` documentation. The Note should keep its Extra and, under §13, state the correction with that citation.

### 70 The Perceptron Trick

**Sources**
1. CampusX, "Logistic Regression Part 1 | Perceptron Trick", XNXzVfItWGY, 47:06. `70-campusx-perceptron-trick.txt` (YouTube's English caption track; the Hindi track is in `70-campusx-perceptron-trick.hi-orig.txt`).
2. No StatQuest, 3Blue1Brown or Khan Academy video teaches the perceptron trick (searched "StatQuest perceptron": only "The Essential Main Ideas of Neural Networks", which is about networks, not this update rule). **No outside video.**

**Teaching path** (CampusX is the only source)
1. [CX 02:34–04:41] When logistic regression applies: CGPA (x-axis) vs IQ (y-axis), green = placed, blue = not placed; the data must be (almost) linearly separable; a ring-shaped non-linear dataset is the counter-example.
2. [CX 06:16–08:25] The goal in plain words: find A, B, C so that the line Ax + By + C = 0 splits the two classes. Use the general form, not y = mx + c; add Dx₃ for a third feature (a plane), and so on (hyperplane).
3. [CX 08:56–14:45] The trick as a story, before any maths: start with a random line; loop (say 1,000 times); pick a random student and "ask" the point whether it is happy. A correctly classified point says "no problem", nothing changes; a misclassified point says "move towards me", and the line moves. Stop after a fixed number of loops or when no point is misclassified (convergence).
4. [CX 14:45–17:56] Which side is positive: Desmos plot of 2x + 3y + 5 = 0; plug a point into Ax + By + C: > 0 positive side, < 0 negative side, = 0 on the line.
5. [CX 17:56–21:34] How A, B, C move the line, live in Desmos: changing C shifts the line up/down; changing A or B rotates it.
6. [CX 22:05–27:49] Moving the line towards a point, four-point Desmos demo with line 2x + 3y + 5 = 0: a negative point in the positive region → append 1 to its coordinates and subtract from (A, B, C); a positive point in the negative region → add. After each update the point is on its correct side.
7. [CX 27:49–30:24] Small steps: multiply the point by a learning rate (about 0.01 or 0.1) before subtracting, so the line moves a little each time: new = old − η·(x, y, 1).
8. [CX 30:55–35:12] Notation: C → w₀, A → w₁, B → w₂; add a column x₀ = 1, so the line is Σ wᵢxᵢ = 0; predict "placed" if w·x ≥ 0.
9. [CX 35:46–41:35] The two-condition algorithm (negative in positive region: w = w − ηx; positive in negative region: w = w + ηx).
10. [CX 42:07–46:23] The single rule w = w + η(y − ŷ)x, checked against the four cases (placed/placed, not/not, placed/predicted not, not/predicted placed): y − ŷ = 0, 0, +1, −1.

3. Plotly frames: the four cases of y − ŷ as a 2×2 grid, each lighting up with its point on the plot and the update it causes (none, none, add, subtract).

### 72 The Sigmoid Function

**Sources**
1. CampusX, "Logistic Regression Part 3 | Sigmoid Function | 100 Days of ML", ehO0-6i9qD4, 40:44. `72-campusx-sigmoid-function.txt`.
2. StatQuest, "StatQuest: Logistic Regression", yIYKR4sgzI8, 8:47. `72-statquest-logistic-regression.txt`.
3. StatQuest, "Logistic Regression Details Pt1: Coefficients", vN5cNN2-HWE, 19:02. `72-statquest-logistic-coefficients.txt`.

**Teaching path**
1. [CX 00:30–01:33] Recap the flaw: the perceptron stops once every point is correct, so its line can hug one class; logistic regression leaves an equal margin.
2. [CX 02:04–07:49] The new idea in words: every point acts on the line. Misclassified points pull it closer, correctly classified points push it away. Strength depends on distance: a misclassified point near the line pulls gently, far away pulls hard; a correct point near the line pushes hard, far away pushes gently. The line settles where the pushes balance, in the middle.
3. [CX 08:21–14:42] Why the old rule cannot do this: w_new = w_old + η(y − ŷ)x; with the step function ŷ is 0 or 1, so for every correct point y − ŷ = 0 and nothing happens. We must change how ŷ is computed.
4. [CX 15:13–17:53] The sigmoid σ(z) = 1/(1 + e^(−z)): very large z → close to 1, very negative z → close to 0, z = 0 → exactly 0.5; any input is squeezed into (0, 1).
5. [SQ-LR 03:23–04:27] Picture of the same S-curve as a probability: mice obese/not obese against weight; heavy mouse → high probability, intermediate → 0.5, light → low; classify as obese if > 50%. Why it clicks: one feature, the curve is the model.
6. [CX 17:53–26:21] Probability map on the CGPA–IQ plane: σ = 0.5 on the line, lines parallel to it at 0.6, 0.7, 0.8 … on the positive side and 0.4, 0.3 … on the other; a gradient of placement chance. P(not placed) = 1 − P(placed), e.g. 0.7 → 0.3. Even the topper has some chance of not being placed.
7. [CX 26:52–33:48] Four-point worked example: predicted 0.8, 0.65, 0.3, 0.15 for two positive and two negative points; y − ŷ = 0.2, −0.65, 0.7, −0.15 is never 0, so every point moves the line: correct points push, misclassified ones pull.
8. [CX 34:21–37:58] Distance sets the strength: two correct points with z = 10 (far) and z = 0.33… (near) give σ ≈ … and update sizes in which the nearer point pushes harder (the captions give 0.6 vs 0.2 for the y − ŷ factors).

**Sources**

### 88 Naive Bayes: The Mathematics

**Sources**
1. CampusX, "Naive Bayes Classifier | Part 7 | Mathematics behind Naive Bayes Algorithm", 2PVRG45eVrY, 19:08 (audio length). `88-campusx-naive-bayes-maths.whisper.txt` (~ times estimated).
2. StatQuest, "Naive Bayes, Clearly Explained!!!", O2L2Uv9pdDA, 15:12. `87-statquest-naive-bayes.txt` (no derivation; used only for the "scores are proportional to posteriors" remark at 05:15–05:47).

**Teaching path** (CampusX carries the maths)
1. [CX ~00:30–02:01] General notation: features x = (x₁, …, xₙ); classes C₁ … C_K; mapped onto the cricket example (x₁ toss, x₂ venue, x₃ outlook; C₁ win, C₂ loss).
2. [CX ~02:01–03:32] For every class compute P(C_k | x); Bayes gives P(x | C_k)·P(C_k)/P(x); drop P(x), common to all classes.
3. [CX ~04:02–05:33] P(x | C_k)·P(C_k) = P(x, C_k) = P(x₁, x₂, …, xₙ, C_k) (commas mean "and").
4. [CX ~06:03–10:36] Chain rule of conditional probability: peel off one variable at a time with P(A, B) = P(A | B)·P(B): P(x₁ | x₂, …, xₙ, C_k)·P(x₂ | x₃, …, xₙ, C_k)·…·P(xₙ | C_k)·P(C_k). This step is exact.
5. [CX ~11:36–14:39] The naive assumption: each P(xᵢ | other features, C_k) is replaced by P(xᵢ | C_k) — conditional independence of features given the class (e.g. P(toss lost | Mumbai, sunny, win) ≈ P(toss lost | win)).
6. [CX ~15:09–16:39] Result: P(C_k | x) ∝ P(C_k) ∏ P(xᵢ | C_k); with the evidence put back, = (1/Z) P(C_k) ∏ P(xᵢ | C_k), Z = P(x) (following Wikipedia's notation).
7. [CX ~17:10–18:41] Decision: ŷ = argmax_k P(C_k) ∏ P(xᵢ | C_k), the maximum a posteriori (MAP) rule.
8. [SQ 05:15–05:47] Plain-language reminder: the number compared is a score proportional to the posterior, not the posterior itself.

- A numeric check of one chain-rule factor on the cricket data (e.g. P(toss lost | Mumbai, sunny, win) has no data vs P(toss lost | win) = 1/5) would make step 5 concrete before the general formula (NOTE-RULES §11 step 3).

### 92 Support Vector Machines: The Geometric Intuition

**Sources**
1. CampusX, "Support Vector Machines | Geometric Intuition", ugTxMLjLS8M, 11:59 (audio length). `92-campusx-svm-intuition.whisper.txt` (~ times estimated; the last 30 s are whisper noise).

**Teaching path**
1. [SQ 00:32–02:07] Start in one dimension: mice by mass, red = not obese, green = obese. 2. [SQ 02:07–03:10] Terminology on that picture: the shortest distance from the observations to the threshold is the **margin**; the midpoint makes it as large as possible (move left or right and it shrinks); this is the **maximal margin classifier**.
3. [CX ~01:00–02:00] Two dimensions: green and red points, two lines π₁ (black) and π₂ (blue) that both classify 100% of the training data. Logistic regression treats them as equal; SVM asks which is better.
4. [CX ~02:00–03:31] Why the wider gap is better: the distance of a point from the line, wᵀx, drives logistic regression's confidence; a line that keeps all points far away should generalise better to unseen data.
5. [CX ~04:01–07:33] The procedure: pick a line π; slide a parallel copy towards the green side until it touches the first green point (π⁺), and another towards the red side (π⁻); the distance between them is the margin d; repeat for many lines; keep the one with the largest d (the margin-maximising hyperplane, wᵀx + b = 0).
6. [CX ~08:03–08:34] π versus π′: d′ < d, so SVM picks π.
7. [CX ~09:04–09:34] Support vectors: the points that π⁺ and π⁻ touch; they alone fix the line.
8. [SQ 03:42–04:14] The weakness of the maximal margin: one outlier near the other class drags the threshold next to it (leads to the soft margin, Note 94).
9. [SQ 07:19–10:28] Dimensions: 1-D data → a point; 2-D → a line; 3-D → a plane; 4-D+ → a hyperplane (all are "flat affine subspaces").

**Teaching path** (CampusX only)
1. [CX ~00:00–01:30] Goal: find w and b of the hyperplane whose distance between π⁺ and π⁻ is largest.
2. [CX ~01:30–05:32] Decision rule from vectors: w is perpendicular to π, π⁺, π⁻; project a new point u onto w; if the projection passes a threshold c the point is positive → w·u + b ≥ 0 ⇒ +1, else −1.
3. [CX ~05:32–09:33] The same rule in 2-D with numbers on Desmos: line 2x + 3y − 3 = 0; point (2, 3): 4 + 9 − 3 = 10 > 0 (captioned as 7) → positive; point (−2, 0): −4 + 0 − 3 = −7 < 0 → negative; the ≥ 0 region shaded.
4. [CX ~11:34–15:05] Choose π⁺: wᵀx + b = +1 and π⁻: wᵀx + b = −1. Equal magnitudes keep π in the middle; the value 1 only fixes a scale.
5. [CX ~16:05–21:07] Desmos demonstration: multiplying w and b by 10 leaves π unchanged but pulls π⁺ and π⁻ closer; dividing by 10 pushes them apart. So the size of w controls the margin.
6. [CX ~22:07–27:39] Constraints: green points satisfy wᵀxᵢ + b ≥ 1, red points ≤ −1 (support vectors exactly ±1); with labels yᵢ = ±1 both become yᵢ(wᵀxᵢ + b) ≥ 1.

8. [CX ~32:11–33:11] Optimisation: maximise 2/‖w‖ over w, b subject to yᵢ(wᵀxᵢ + b) ≥ 1 for all i.
9. [CX ~33:11–34:42] Limit: one point on the wrong side makes the constraints impossible, so this hard-margin SVM needs perfectly separable data; the soft margin comes next.

### 94 SVM Mathematics: The Soft Margin

**Teaching path**
1. [SQ 03:42–04:44] The problem in one dimension: one not-obese outlier sits among the obese mice; the maximal-margin threshold hugs it, so a new mouse near the obese group is called not obese. Allow one misclassification and put the threshold between the main groups instead.

3. [SQ 05:46–06:49] How many mistakes to allow: cross-validation picks the soft margin (e.g. one misclassified point and two correct points inside the margin); points on the edge or inside the soft margin are the support vectors, giving the name **support vector classifier**.
4. [CX ~00:00–03:31] The same failure in the maths: the hard-margin constraints yᵢ(wᵀxᵢ + b) ≥ 1 cannot all hold when even one point is on the wrong side; real data is only almost separable.

6. [CX ~04:32–06:02] Add Σ ζᵢ (slack, usually written ξᵢ) to the loss: one non-negative number per point.
7. [CX ~06:02–08:33] What the slack is: 0 for points on the correct side of their own hyperplane (green above π⁺, red below π⁻); for the others, how far they sit on the wrong side of their own hyperplane (see Contradictions for the unit).
8. [CX ~08:33–09:34] Loss = margin error (‖w‖/2) + classification error (Σ ξᵢ).
9. [CX ~10:04–12:05] Weight the second term by C: large C (10,000) → avoid mistakes, accept a narrow margin; small C (0.001) → keep the margin wide, accept mistakes; tune C with grid search and cross-validation. Two pictures: a narrow margin with no mistakes vs a wide margin with two mistakes.
10. [CX ~12:35–13:35] Same shape as regularised logistic regression: hinge loss + regularisation, with C ∝ 1/λ, which is why scikit-learn's `LogisticRegression` also uses C.
11. [CX ~14:05] "Soft" because the criterion is relaxed: mistakes are allowed at a price.

**Contradictions**
- Unit of the slack: CampusX calls ζᵢ the point's "distance" from its hyperplane, and the Note (§4.2) says "its distance from its own hyperplane". ### 116 AdaBoost Step by Step

**Sources**
1. CampusX, "AdaBoost - A Step by Step Explanation", RT0t9a3Xnfw, 19:24 (audio length). `116-campusx-adaboost-step-by-step.whisper.txt` (~ times estimated; the code part of the video is in Note 117).

**Teaching path**
1. [CX ~00:30–02:00 + SQ 04:09–04:39] Every row starts with sample weight 1/n (CX: 5 rows → 0.2; SQ: 8 patients → 1/8), so the weights sum to 1.
2. [SQ 05:10–06:14 + CX ~02:00–03:01] Fit the first stump: try each variable (SQ: chest pain, blocked arteries, patient weight with best threshold 176) and keep the lowest Gini / highest information gain.
3. [SQ 06:45–07:17 + CX ~09:34–10:34] Total error = sum of the sample weights of the misclassified rows (SQ: one error → 1/8; CX: two errors → 0.4); it lies between 0 and 1.
4. [CX ~05:02–09:04] Why α has the shape it has: model A always right (error 0), model B always wrong (error 1), model C right half the time (0.5). 5. [SQ 07:17–10:25 + CX ~09:04–11:04] The formula α = ½ ln((1 − error)/error), drawn as a curve. Numbers: SQ error 1/8 → α = 0.97, error 3/8 → 0.42; CX error 0.4 → α ≈ 0.20. If error is exactly 0 or 1, add a small constant.

8. [SQ 15:07–15:39] Either use the weights directly in a weighted Gini index, or…
9. [SQ 15:39–18:15 + CX ~14:36–18:07] …build a new dataset of the same size by drawing rows with probability equal to their weight: lay the weights end to end on [0, 1] as ranges, draw random numbers (CX: 0.13, 0.43, 0.62, 0.50, 0.8 → rows 1, 3, 3, 3, 4); heavy rows appear several times; then reset all weights to equal (SQ 18:15).
10. [SQ 18:15–18:46 + CX ~18:07–19:08] Repeat for the next stump; finally predict with the weighted vote sign(Σ αₜhₜ(x)) (SQ: add the amounts of say of the stumps voting for each class, larger sum wins).
