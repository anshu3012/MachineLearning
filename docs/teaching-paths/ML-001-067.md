### Contradictions and clashes found

Where a Note teaches something that points the wrong way (fix needed):
1. **Note 20 §8 / §8.1:** "Minimum/maximum = ends of the whiskers = calculated fences." Wrong: in the five-number summary the minimum and maximum are the data extremes (KA box plot 00:30–01:00); the fences only flag outliers, and the Note itself ends the whiskers at the last value inside them (0.42 and 64, not 64.81).
2. **Note 3 §5 key point:** "In reinforcement learning, there is no data." The agent has no ready-made labelled dataset but learns from the experience it collects (Sutton and Barto 2018 §1.1).
3. **Note 66 §6:** "With a single feature there is little to gain from Ridge" contradicts Note 63 and SQ Ridge (two training points, one feature: 1.69 → 0.74, lower test error). Scope it: the gain is largest with many or correlated features; with one feature it helps when data are few.
4. **Note 27 §3.2:** the dummy-variable trap is taught as a universal rule; scikit-learn's `OneHotEncoder` docs say dropping a column matters for unregularised linear models and can bias penalised ones. Scope it.
5. **Note 19 §9.2:** "Richer passengers… were taken to the lifeboats first" explains a correlation causally without a source (SQ Pearson 03:30: correlation is not causation). Source it or remove it.
6. **Note 1 §3.3:** the main text repeats "whether we give it two, four or ten numbers, it adds them all"; its own Extra correctly says a model expects the number of inputs it was trained on. Align the main sentence with the Extra.
7. **Note 30 §2 key point:** "linear and logistic regression work better when features are close to normal" is framed like an assumption; the normality assumption is on the errors (Kutner §1.8), and the Note's Extra already says so. Keep only the measured, practical claim.

Where CampusX and an outside source disagree (the Note must pick and say why):
8. **Note 49:** CampusX standardises MNIST pixels before PCA; SQ says scale only features on different scales; the Note's own experiment shows standardising costs 1.4–2.8 accuracy points. The Note is right.
9. **Note 52:** SQ says R² is always 0–1; CampusX says it can be negative. Both hold in their setting: 0–1 on training data for least squares with an intercept, negative possible on test data (scikit-learn `r2_score` docs). State both.
10. **Note 62:** SQ and CampusX define variance as the train/test gap; the formal definition is the spread of the fitted model across training sets (ESL §7.3, ISL §2.2.2). The Note uses the formal one and is right; mention the gap as a symptom.
11. **Note 26:** SQ uses "label encoding" for arbitrary numbers on input features; scikit-learn's `LabelEncoder` is for the target only (CampusX). Note the loose usage.
12. **Note 20 vs KA:** whiskers to min/max (KA) vs whiskers to the 1.5 IQR fences (CampusX, the Note). Both styles exist (Tukey 1977); the Note should name the style it uses.
13. **Notes 43–44:** KA computes quartiles as medians of halves and percentile ranks by counting (two conventions); pandas interpolates. Small datasets give different numbers; the Note should say which method its numbers use.
14. **Notes 59–60:** SQ notes that "SGD" is commonly used for mini-batch training; CampusX keeps the names separate. Mention both usages.

Version facts (no teaching clash; the Notes are already right): `error_bad_lines`/`squeeze` removed from `read_csv` (Note 15), `sparse` → `sparse_output` (Notes 27–29), `np.timedelta64(1, "M")` refused by pandas (Note 34), `np.linalg.inv` vs `solve`/`lstsq` (Note 55).

### 06 Instance-based vs model-based learning

**Sources**

5. 09:00–10:30 CampusX: poor-quality data (missing values, outliers, formats); ~60 percent of project time is data cleaning ("garbage in, garbage out").
6. 10:30–12:30 CampusX: irrelevant features: predicting who joins a marathon from weight, height, age, location; location says nothing about fitness, drop it; combine features (feature engineering).
